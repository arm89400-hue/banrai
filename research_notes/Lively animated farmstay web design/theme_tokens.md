Brand under consideration: Baanrai farmstay. Current tokens: farm green hsl(150,35%,30%), dark green hsl(150,35%,20%), rice-straw gold hsl(38,48%,64%) reserved for the one main booking button, page off-white hsl(40,30%,97%), Georgia logo text, IBM Plex Sans Thai body.

|---|---|---|
| farm green hsl(150,35%,30%) | #32674d | oklch(0.470 0.073 160) |
| dark green hsl(150,35%,20%) | #214533 | oklch(0.357 0.052 160) |
| rice-straw gold hsl(38,48%,64%) | #cfaf77 | oklch(0.770 0.082 81) |

## 1. Token structure (primitive -> semantic -> component), CSS custom properties, DTCG format status, OKLCH / color-mix(), APCA vs WCAG 2

### Takeaway
Use three tiers: private primitive/palette tokens (e.g. `--green-470`), public semantic/alias tokens by role (`--color-bg-action`, `--color-text-muted`), and a few component tokens only where needed. Author colors in OKLCH, derive hover/soft/border variants with `color-mix(in oklch, ...)` or relative color syntax, and check contrast with WCAG 2.2 (legal baseline) and optionally APCA as a second check. The W3C DTCG format reached its first stable version (2025.10) in Oct 2025, so a small JSON token file is now a reasonable source of truth, though for a single React/Vite site plain CSS custom properties are enough.

### Cited Findings
- The Design Tokens Community Group released its first stable spec, "2025.10", on 28 Oct 2025, described as a production-ready, vendor-neutral format; headline features include theming / multi-brand support, Display P3 and OKLCH (all CSS Color 4 spaces), inheritance, aliases and component-level references. Final reports exist for Format, Color and Resolver modules. — [W3C DTCG announcement](https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/); [designtokens.org](https://designtokens.org/)
- The DTCG FAQ says the core format is stable for production but still evolving, and it is not on the W3C Standards Track (it is a Community Group report). Adopters/participants listed include Figma, Sketch, Penpot, Adobe, Style Dictionary, Tokens Studio, zeroheight, Zeplin. — [DTCG FAQ](https://www.designtokens.org/faq/)
- DTCG format details: a token requires `$value`; `$type` is optional if inherited from a group or resolvable via alias; `$description`, `$extensions`, `$deprecated` optional. Aliases use curly braces `{group.token}`; JSON Pointer `$ref` can target parts of a value. Groups can `$extends` another group (deep merge). Simple types: color, dimension, fontFamily, fontWeight, duration, cubicBezier, number; composite: strokeStyle, border, transition, shadow, gradient, typography. Duration = `{ "value": 200, "unit": "ms" }`; cubicBezier = `[P1x, P1y, P2x, P2y]` with x in 0..1; transition = `{duration, delay, timingFunction}`. Colors are objects with `colorSpace` and `components` (plus optional alpha, hex). File extension `.tokens` / `.tokens.json`, media type `application/design-tokens+json`. — [DTCG Format 2025.10](https://www.designtokens.org/tr/2025.10/format/)
- Shopify Polaris (v11) uses two layers: private palette tokens (10 shades per hue) used only to build aliases, and public alias tokens that designers/devs use; tokens are exposed as CSS variables for custom UI in Shopify admin. — [Polaris v11 tokens](https://polaris.shopify.com/whats-new/version-11-tokens); [Polaris v11 color](https://polaris.shopify.com/whats-new/version-11-color)
- Evil Martians (Sitnik & Turner, updated 17 Sep 2025): HSL's `l` is not perceptual, so the same lightness change looks different across hues and hue changes can break contrast; OKLCH's L is perceptual, so palettes generated by formula are predictable; OKLCH can encode P3 colors. Guidance: define every color as a custom property, components reference tokens only (`var(--error)`), reuse colors, implement dark/high-contrast themes by swapping custom properties rather than per-component `@media`, derive states (hover) with relative colors, and optionally lint to forbid hex/rgb/hsl. All current browsers support `oklch()` and relative colors; Chrome/Safari clip out-of-gamut colors (hue can shift), so give sRGB fallbacks and wrap P3 values in `@media (color-gamut: p3)`. — [Evil Martians: OKLCH in CSS](https://evilmartians.com/chronicles/oklch-in-css-why-quit-rgb-hsl)
- Practitioner pattern: convert a brand color to OKLCH, store it as one source token, derive hover/soft/border variants with `color-mix(in oklch, ...)` against black/white; if percentages sum to less than 100% the remainder becomes transparency; this does not automatically create an accessible palette, contrast must still be tested. — [Flavio Copes: oklch() and color-mix()](https://flaviocopes.com/css-oklch-color-mix/)
- Contrast standards: WCAG 2.2 (Oct 2023) is the current W3C Recommendation and the baseline referenced by laws; WCAG 2's minimum body-text ratio is 4.5:1 and ignores font size/weight beyond the large-text exception, while APCA accounts for size and weight and is not backwards compatible with WCAG 2 ratios. — [CivicActions blog](https://blog.civicactions.com/all-models-are-wrong-but-some-are-useful-choosing-the-right-contrast-model-for-accessibility-905bb31ad032); [APCA introduction (Myndex)](https://github.com/myndex/apca-introduction)
- APCA was pulled from the WCAG 3 working draft (July 2023) for lack of working-group support; as of April 2026 WCAG 3's contrast method remains undetermined. One 2026 vendor source claims APCA is "currently part of the WCAG 3 draft" — this conflicts with the more detailed accounts and should be treated as wrong/outdated. — [Adrian Roselli, "WCAG3 Contrast as of April 2026"](https://adrianroselli.com/2026/04/wcag3-contrast-as-of-april-2026.html) (page timed out on fetch; claim taken from search snippet); [Eric Eggert, "WCAG 3 is not ready yet" (updated Sep 2024: "APCA is not in the current draft")](https://www.yatil.net/blog/wcag-3-is-not-ready-yet); contradicted by [pravinkumar.co 2026](https://pravinkumar.co/blog/apca-color-contrast-webflow-design-2026)
- Recommendation from Eggert: for commercial/public projects use WCAG 2 contrast; passing both WCAG 2 and APCA gives stronger accessibility than WCAG 2 alone. — [yatil.net](https://www.yatil.net/blog/wcag-3-is-not-ready-yet)

### Inferences
- Concrete tier sketch for Baanrai (CSS, no build tool needed):
  - Primitives (private, never used in components): `--green-35: oklch(0.357 0.052 160)`, `--green-47: oklch(0.470 0.073 160)`, `--straw-77: oklch(0.770 0.082 81)`, `--paper-98: oklch(0.980 0.004 85)`, plus a neutral ink and a few status hues.
  - Semantic: `--color-bg-page`, `--color-bg-surface`, `--color-text`, `--color-text-muted`, `--color-action` (green: links, secondary buttons, selected states), `--color-action-hover`, `--color-cta-bg` (straw gold, one per page), `--color-cta-text` (dark green — white on gold fails at 2.09:1), `--color-selected-bg`, `--color-border`, `--color-success/-warning/-danger/-info` (+ `-soft` tints for backgrounds).
  - Component (only where a component genuinely deviates): `--btn-cta-bg: var(--color-cta-bg)`, `--calendar-day-selected-bg: var(--color-selected-bg)`.
- Because OKLCH L is perceptual, a tint scale can be produced by holding hue 160 and stepping L (e.g. 0.97, 0.93, 0.85 ... 0.30) while reducing chroma at the extremes; `color-mix(in oklch, var(--green-47) 12%, var(--paper-98))` gives a soft selected background that stays on-brand.
- Since gold-on-paper is 1.97:1, gold must stay a filled-button/background color only, which matches the "reserved for the main booking button" rule; never use it for text, icons or thin borders on the off-white page.
- A DTCG `.tokens.json` file is only worth it if the owner wants Figma round-tripping; for this repo a single `tokens.css` with commented tiers is the pragmatic equivalent.

## 2. Motion tokens: duration and easing scales (Material 3, Carbon, Fluent, Atlassian), naming and application

### Takeaway
Every major system uses a small named duration scale (roughly 50-700 ms) plus 3-4 named easing curves split by intent (standard / enter / exit, or productive / expressive). Common rules: scale duration to element size and distance, keep frequent interactions under ~150 ms, make exits faster than entrances, use one focal motion at a time, and turn motion off (instant) under `prefers-reduced-motion`.

### Cited Findings
- IBM Carbon duration tokens: `duration-fast-01` 70ms (buttons, toggles), `duration-fast-02` 110ms (fades), `duration-moderate-01` 150ms (small expansions), `duration-moderate-02` 240ms (expansion, toasts), `duration-slow-01` 400ms (large expansions, important notifications), `duration-slow-02` 700ms (background dimming). Easing: productive standard `cubic-bezier(0.2, 0, 0.38, 0.9)`, entrance `(0, 0, 0.38, 0.9)`, exit `(0.2, 0, 1, 0.9)`; expressive standard `(0.4, 0.14, 0.3, 1)`, entrance `(0, 0, 0.3, 1)`, exit `(0.4, 0.14, 1, 1)`. Use productive for task moments, expressive sparingly for significant moments; standard when element stays visible, entrance when appearing, exit when leaving permanently; micro-interactions ease-out, ~90-120 ms; provide reduced/static alternatives. — [Carbon motion](https://carbondesignsystem.com/elements/motion/overview/)
- Atlassian: interactions 50-150 ms (list hover 50 ms), transitions 150-400 ms (dropdown enter 150 ms, modal enter 250 ms). Easings: ease-out bold `cubic-bezier(0, 0.4, 0, 1)` (panels entering), ease-in-out bold `(0.4, 0, 0, 1)` (scaling modals, repositioning), ease-in practical `(0.6, 0, 0.8, 0.6)` (exits), ease-out practical `(0.4, 1, 0.6, 1)` (popups, hover fades). Semantic motion tokens bundle duration + easing + property by intent, e.g. `motion.popup.enter` (behind a feature flag, limited component coverage). Rules: if triggered "dozens of times a day, keep it under 150ms"; scale duration to element size; exits faster than entrances; one focal point; never make users wait. Reduced motion: motion off and instant; avoid flashing, rapid oscillation, large sweeps; UI must work with motion disabled. — [Atlassian motion](https://atlassian.design/foundations/motion)
- Material 3: duration tokens include short1 = 50 ms, medium2 = 300 ms, long2 = 500 ms (M3 has short1-4, medium1-4, long1-4, extra-long1-4 steps). Easing families: emphasized, emphasized-decelerate, emphasized-accelerate, standard (+accelerate/decelerate), legacy. — [Flutter Easing class](https://api.flutter.dev/flutter/material/Easing-class.html); [KPay design docs listing M3 durations](https://design.kpay-group.com/docs/motion/type/flutter-type/flutter-intro); [design.md issue #47](https://github.com/google-labs-code/design.md/issues/47)
- `cubic-bezier(0.2, 0, 0, 1)` is widely cited as M3 "Emphasized" (others label the same curve "standard" or "snappy") — sources disagree on labels; official m3.material.io page did not render on fetch. — [cem-theme timing tokens](https://unpkg.com/@epa-wg/cem-theme@0.0.14/dist/lib/tokens/cem-timing.xhtml); [brand.snyder.tech motion](https://brand.snyder.tech/motion)
- Fluent 2 motion page gives principles only (no token values on that page): give larger elements more time than smaller ones; linear only for constant-rate things like rotation; ease-in / ease-out / ease-in-out described. — [Fluent 2 motion](https://fluent2.microsoft.design/motion)

### Inferences
- A small site needs about 4 durations and 3 easings, named by intent, e.g.:
  - `--dur-instant: 80ms` (press, toggle), `--dur-quick: 150ms` (hover, dropdown), `--dur-base: 240ms` (panels, accordions, toasts), `--dur-slow: 400ms` (page-level reveals, hero photo fade); optionally `--dur-ambient: 700ms+` for decorative/background only.
  - `--ease-standard: cubic-bezier(0.2, 0, 0, 1)`, `--ease-enter: cubic-bezier(0, 0, 0.3, 1)`, `--ease-exit: cubic-bezier(0.4, 0, 1, 1)` (exit ~20-30% shorter than enter).
  - Semantic bundles like Atlassian: `--motion-menu-enter: var(--dur-quick) var(--ease-enter)`.
- Under `@media (prefers-reduced-motion: reduce)` set durations to ~0 for movement (keep short opacity fades if desired), per Atlassian's "off and instant" rule.
- Admin dashboard should use only the "productive" end (instant/quick), guest pages may use one expressive moment (e.g. booking confirmation), mirroring Carbon's productive vs expressive split.

- Fluent 2 token values (e.g. durationUltraFast, curveEasyEase) not retrieved.

## 3. Deriving palettes from place, photography and materials; number of colors; roles; avoiding "earthy cream + terracotta" defaults

### Takeaway
Hospitality identities that feel specific take color from a named feature of the actual place (desert dusk rock, local textile and laterite soil, coastline photography) rather than a generic "natural" mood. Keep the functional palette small: one brand hue family, one rare accent, neutrals, and status colors, with each color assigned a role.

### Cited Findings
- Amara Resort & Spa (Arizona, by Fine): palette echoes the desert at dusk, with raspberry shades from the surrounding rock formations. — [Fine: Amara](https://www.wearefine.com/work/amara-resort-and-spa/)
- Jay Bhoomi Retreat (Odisha, India): colors drawn from deep reds, burnt earths and muted ochres of Odisha's Sambalpuri textiles and laterite soil — a palette tied to specific local materials. — [sghosh.com](https://sghosh.com/project/brand-identity-for-jay-bhoomi-retreat-luxury-hotel)
- Ebb hotel, Dunedin: identity flows from an initial artwork and the concept of ebb and flow, with commissioned aerial, landscape and close-up photography of the coastline used across materials (the source does not say colors were extracted from photos). — [BP&O: Ebb Dunedin](https://bpando.org/2022/04/28/hotel-branding-ebb-dunedin/)
- Lake House (Lake Placid): minimal palette with a single rustic red corporate color, natural textures and landscape photography. — [We and the Color](https://weandthecolor.com/lake-house-hotel-brand-identity/45011)
- Mana Hotels: each location gets its own palette (Palanga reflects the sunlit coast). — [Abduzeedo](https://abduzeedo.com/node/88836)
- Practitioner advice for seasonal accents: change button color or a nav highlight rather than redesigning; keep text in a dark readable color (bright festive colors are hard to read). — [Sperling Interactive](https://www.sperlinginteractive.com/blog/how-to-have-a-great-seasonal-website/); [Designmodo: avoiding cliché holiday design](https://designmodo.com/holiday-websites/)

### Inferences
- For Baanrai the existing palette already follows the place-derived pattern: green from the orchard canopy, gold from rice straw. To stay away from generic "cream + terracotta", name each token after the real material it was sampled from (e.g. "straw", "canopy", "soil", "teak") and sample values from the farm's own photographs (eyedrop leaf, straw, soil, wood in the hero photos, then normalize in OKLCH).
- Suggested functional count: 1 brand hue (green) at 2-3 lightness steps, 1 rare accent (straw gold, one CTA per page), 2-3 warm neutrals (paper, surface, ink), 4 status colors (success/warning/danger/info) tuned to sit near the brand hues. A wood/soil brown can be a fourth decorative tone for illustration or photo frames only, not for actions.
- Role rules: action = green (links, secondary buttons, focus ring); selected = green soft tint + green border; primary CTA = straw gold with dark-green text; status colors never reused as decoration.

### Gaps
- No 2023-2026 Pentagram or studio case study specifically about a farm/agritourism website palette was found; examples are hotel identities, several of them pre-2023 (Ebb 2022).
- No source quantified how many colors small brands should use; the count above is an inference.

## 4. Seasonal / time-of-day / data-driven theming (examples, risks, implementation)

### Takeaway
Time-based theming is a real, working pattern on personal and small sites (sunrise/day/sunset/night palettes, hue-by-day-of-year), implemented with CSS custom properties updated by a small script, ideally blending with `color-mix(in oklch)`. Risks: flash of wrong colors on load, contrast failures in some stages, unexpected appearance changes, animated color shifts ignoring reduced-motion. Safest version for a business site: change only one accent/illustration layer (e.g. the "ripe this month" fruit color), never the CTA or text colors, and give a manual override.

### Cited Findings
- localghost.dev (Sophie Koonin, 5 Jul 2026): four stages (sunrise, day, sunset, night), each with three OKLCH colors; uses `Temporal.Now.plainTimeISO()` for local time; a 90-minute transition window feeds a percentage into `color-mix(in oklch, next X%, current)`; colors written to `--bg-gradient-*` custom properties registered via `CSS.registerProperty` as `<color>` so they can transition; a `data-time` attribute on root enables stage-specific styles (stars at night); a picker lets visitors override, saved in sessionStorage; Date-based shim for browsers without Temporal (Safari). Limitations: fixed clock times not real sun position; a flash of wrong colors persists in Firefox even with an init script; Safari background glitch; post does not address `prefers-reduced-motion` or contrast in each stage. — [localghost.dev](https://localghost.dev/blog/time-based-background-colour-transitions-with-temporal-and-css-color-mix/)
- Seasonal.css: maps each day of the year to a hue on the color wheel, derives foreground/background/highlight shades, and serves them as CSS variables (variables-only option available); self-hostable via Docker. — [jes/seasonal-css](https://github.com/jes/seasonal-css)
- Bayton.org switched to a darker theme in the evening with CSS transitions (fade, not abrupt), user override saved in localStorage. — [bayton.org](https://bayton.org/blog/2017/02/introducing-night-mode-on-bayton-org/) (2017, older than preferred range)
- A "circadian" JS library animates site colors over 24 h using SunCalc for real sunrise/sunset by location. — [Substack: time-of-day responsive themes](https://shawnfromportland.substack.com/p/create-time-of-day-responsive-color)
- WordPress block theme MRseasons ships one style variation per season, switched with one click. — [MRseasons](https://bal.wordpress.org/themes/mrseasons/preview)
- A seasonal retailer has changed banner and color scheme each season since 1999; others note many companies only add seasonal colors rather than a drastic change. — [WebmasterWorld thread](https://www.webmasterworld.com/forum22/571.htm)

### Inferences
- Data-driven fit for Baanrai: the site already has a "fruit ripe this month" feature; a single `--color-season` token set server- or client-side from the current month (durian, mangosteen, longan, rambutan hues, pre-validated) could tint section dividers, a small badge, or the activities illustration — while `--color-cta-*`, text, and action tokens stay fixed so booking UI never changes.
- Prefer month/season (changes rarely, can be set before first paint from the server or a tiny inline script) over time-of-day (changes during a visit, risks flash and mid-session shifts). Pre-compute each season's palette and check contrast for each, rather than generating hues algorithmically like Seasonal.css.
- Respect `prefers-reduced-motion` for any color transition, and do not let time-of-day force dark mode against the OS setting.

### Gaps
- Found no hospitality/hotel site documented as changing its theme by season or crop; examples are personal sites, tools and retail anecdotes.
- No data on whether seasonal theming affects conversion.

## 5. Dark mode for a small hospitality site: worth it?

### Takeaway
Evidence is mostly agency opinion. Benefits (low-light comfort, photos pop) are real but modest; costs are doubled QA, brand color re-tuning, and readability problems for some users (astigmatism halation). For a photo-led booking site, a well-tuned light theme is the priority; if dark is added, make it follow the OS preference / user choice, never the default, and implement it purely by swapping semantic tokens (cheap with `light-dark()`).

### Cited Findings
- Pros cited: reduced eye strain in low light; content like imagery stands out. Cons: light text on dark can cause halation (blur) for people with astigmatism, possible negative impact for dyslexic users, harder to design and brand. Common recommendation: user-selectable option, not default; test contrast. — [Bop Design (Sep 2023)](https://www.bopdesign.com/bop-blog/2023/09/dark-mode-in-b2b-website-design/); [Limely](https://www.limely.co.uk/blog/the-advantages-disadvantages-of-dark-mode-in-web-design); [Webflow blog](https://webflow.com/blog/benefits-of-dark-mode)
- CSS `light-dark()` reached Baseline (newly available) in May 2024; it picks the first value in light / no preference and the second in dark, and requires `color-scheme: light dark` (usually on `:root`); `color-scheme` also affects browser UI (form controls, scrollbars). Unsupporting browsers fall back to initial values, so provide a fallback if old browsers matter. — [MDN light-dark()](https://developer.mozilla.org/en-us/docs/web/css/color_value/light-dark); [web.dev: Color themes with Baseline CSS features](https://web.dev/articles/baseline-in-action-color-theme); [Adobe compat note](https://shadow-dom-css.adobe.com/features/light-dark)
- Evil Martians: implement dark/high-contrast by changing custom properties, not component-level media queries. — [Evil Martians](https://evilmartians.com/chronicles/oklch-in-css-why-quit-rgb-hsl)

### Inferences
- For Baanrai: skip dark mode for now on guest pages (phone users in daylight, photo-first content on light paper fits the brand); structure semantic tokens so dark could be added later with one `:root` block. Admin used at night by the family might benefit more, but it is optional.
- If added: dark surfaces should be very dark green-tinted neutrals (OKLCH hue ~160, L ~0.18-0.22, low chroma), not pure black; gold CTA likely works as-is with dark text; re-check every status color.

### Gaps
- No hospitality-specific data on dark-mode usage or conversion.

## 6. Keeping one theme consistent across guest pages and an admin dashboard

### Takeaway
Share primitives and semantic tokens between guest site and admin; let the admin differ by density, type size and a calmer, "productive" motion profile, not by a separate palette. Large systems (Polaris for Shopify admin, Carbon productive vs expressive) show the pattern: one token source, different usage modes.

### Cited Findings
- Polaris tokens are applied to components and exposed as CSS variables so custom admin UI matches; palette tokens private, alias tokens public. — [Polaris v11 tokens](https://polaris.shopify.com/whats-new/version-11-tokens)
- Carbon distinguishes productive motion (task-focused) from expressive (significant moments) within one system. — [Carbon motion](https://carbondesignsystem.com/elements/motion/overview/)
- Atlassian: frequent interactions under 150 ms; one focal point; no motion that blocks work. — [Atlassian motion](https://atlassian.design/foundations/motion)
- DTCG 2025.10 supports theming / multi-brand and group `$extends` (deep-merge overrides), the standard mechanism for a variant theme derived from a base. — [DTCG announcement](https://www.w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/); [DTCG Format](https://www.designtokens.org/tr/2025.10/format/)

### Inferences
- Implementation: one `tokens.css` imported by both guest and admin; admin scope (`.admin` or `[data-surface="admin"]`) overrides only density/size tokens (e.g. larger base font per the owner's "bigger text" need, tighter row spacing) and maps status tokens heavily (booking paid / deposit / pending / cancelled = success / info / warning / danger).
- Straw-gold CTA rule should carry into admin: at most one gold primary action per admin screen (e.g. "Confirm booking"); everything else green or neutral.
- Lint or grep for raw hex/hsl in component CSS to keep both surfaces on tokens (Evil Martians' Stylelint suggestion).

### Gaps
- No found case study specifically on hospitality guest site + owner admin sharing a theme; guidance is extrapolated from Polaris/Carbon.
